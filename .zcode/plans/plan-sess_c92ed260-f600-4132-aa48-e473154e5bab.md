## Corrected premise (from verified findings)

The lxml correction is confirmed: `html_extractor.py:984` calls `_new_soup(raw_html, "lxml")` as the primary parser, with `html5lib` (line 1007) in the recovery path. Both are native code, pinned in `requirements.txt`. **Subprocess isolation applies to all fixtures, not just PDFs.** The worker protocol must be generic; PDF fixtures adopt it first, HTML switches in behind a flag.

Grounded platform facts:
- CI is **Linux-only (ubuntu-24.04)** but **Python is not wired into CI at all** — no `setup-python`, no pytest job. `CI=true` is set ambiently by GitHub Actions but nothing in `scripts/` checks it.
- Dev environment is **Windows** (spawn-mode subprocess; no `fork`, no `signal.alarm`).
- **No subprocess/pool precedent** exists in the repo — I'm inventing the pattern. The threadpool timeout in `run_eval.py:115` is structurally close but the wrong mechanism (threads can't interrupt native code or survive a segfault).
- Boundary objects are trivially serializable: `body: bytes`, `content_type: str`, `final_url: str`, `host_suffix: str` (child reconstructs `ReplayPolicy`). Returns are plain dataclass/str/tuple/list.
- Body sizes: 4.6 MB prospectus is the outlier; everything else < 390 KB. Path-on-disk avoids queuing it.

## Deliverable 1a — Corpus & baseline identity

### New module: `scripts/eval/corpus_manifest.py`

A pure function `build_manifest(corpus_root) -> dict` that walks every fixture dir and emits:

```json
{
  "evaluation_schema_version": 3,
  "corpus_manifest_hash": "<sha256 over the entries below>",
  "fixtures": [
    {
      "fixture_id": "legacy-asp/example-01",
      "family": "legacy-asp",
      "criticality": "critical",
      "body_sha256": "...",
      "headers_sha256": "...",
      "metadata_sha256": "...",
      "expectations_sha256": "..."
    }
  ]
}
```

- `corpus_manifest_hash` = sha256 over the canonical JSON of the sorted `fixtures[]` list (sorted by `fixture_id`), so any add/remove/change/relabel alters it.
- `criticality` read from `expected.json` (`expected.criticality`, default `"standard"`), so criticality changes also ripple into the hash.
- Missing files contribute `"hash": null` (not a crash) — malformed fixtures surface elsewhere.

### Wire into the report

`run_extraction_eval.main()` attaches the manifest to the report:
```python
report = {
    "evaluation_schema_version": 3,
    "corpus_manifest": manifest,          # the full manifest (debugging)
    "corpus_manifest_hash": manifest["corpus_manifest_hash"],
    "overall": ..., "per_family": ..., "fixtures": results,
    "gate": { ... },                      # see Deliverable 1d
}
```

### Extend `detect_regression` (defect-7 lineage)

Add a `corpus_universe` comparison. When both current and baseline carry `corpus_manifest_hash`:
- Equal hashes → `universe: "unchanged"`.
- Different hashes → `universe: "changed"`, plus a diff of `removed`/`added`/`changed` fixture IDs (set arithmetic on the per-fixture hashes, so "changed body but same id" is distinguishable from "removed+added").
- A changed universe is **not** a regression (exit 2) on its own — but it is **never silently compared** as the same evaluation universe. The report records it; the console prints a warning ("⚠️ corpus universe changed vs baseline — comparison may be misleading").

## Deliverable 1b — Generic subprocess worker protocol

### New module: `scripts/eval/_fixture_worker.py` (single-file, executable entry point)

Invoked as `python scripts/eval/_fixture_worker.py` (reads JSON request from stdin, writes JSON outcome to stdout). This sidesteps `multiprocessing` spawn/pickle machinery entirely and works identically on Windows and Linux.

**Request (stdin JSON):**
```json
{
  "fixture_id": "pdf-download/prospectus",
  "extractor_kind": "pdf",            // or "html"
  "body_path": "/abs/path/body.bin",
  "content_type": "application/pdf",
  "final_url": "https://...",
  "host_suffix": "uettaxila.edu.pk",
  "timeout_ms": 180000
}
```

**Outcome (stdout JSON):**
```json
{
  "status": "success",                // success | extractor_error | timeout | worker_crash | memory_limit | invalid_worker_output
  "result": {                         // present only when status == "success"
    "canonical_url": "...", "title": "...", "markdown": "...",
    "crawl_links": [...], "resources": [{...}], "image_candidates": [{...}],
    "diagnostics": {...}, "extractor_used": "pdf|html",
    "pdf_error": null | {"error_code": "...", "error_message": "..."}
  },
  "duration_ms": 84213,
  "peak_memory_bytes": null,          // set on Linux via resource; null on Windows
  "error_code": null,
  "error_message": null
}
```

The child reads the body from `body_path` (avoids queuing 4.6 MB through pipes), reconstructs the `ReplayPolicy` from `host_suffix`, calls `extract_html_document` or `_extract_pdf` (imported in the child), serializes the `HtmlExtractionResult` fields to JSON. A second extraction for determinism also happens in the child — the child returns both fingerprints, so the parent doesn't re-spawn for the determinism check.

### New module: `scripts/eval/isolation.py`

`run_isolated(request: WorkerRequest) -> WorkerOutcome` wraps the child invocation:

```python
proc = subprocess.run(
    [sys.executable, str(WORKER_PATH)],
    input=json.dumps(request), capture_output=True, text=True,
    timeout=request.timeout_ms / 1000,
    **_linux_limits(),   # preexec_fn on POSIX for RLIMIT_AS/RLIMIT_CPU; no-op on Windows
)
```

- **Timeout**: enforced by `subprocess.run(timeout=...)`. On expiry → `TimeoutExpired` → outcome `status="timeout"`, `error_code="wall_clock_exceeded"`. The child is killed by `subprocess` (entire process tree on `Popen` via `killpg` on POSIX; `proc.kill()` on Windows).
- **Memory limit**: POSIX-only via `preexec_fn=lambda: resource.setrlimit(RLIMIT_AS, (max, max))`. On Windows → `peak_memory_bytes` is `null`, `status="memory_limit"` is reported only if the child dies with a memory-related signal (best-effort). This asymmetry is documented.
- **Worker crash** (non-zero exit, no parseable stdout) → `status="worker_crash"`, `error_code` from return code / signal.
- **Invalid worker output** (stdout not valid JSON or missing fields) → `status="invalid_worker_output"`, `error_code="stdout_not_json"`. **Exit 1** in the parent (per acceptance criteria).

### Timeout tiers (fixture-declared)

`expected.json` may set `"max_duration_ms"` (default by family). PDF tiers per the review: small 30s, normal 90s, large/prospectus 180s. The manifest records the approved ceiling per fixture so a 90s prospectus is not judged against a 30s limit.

### Integration into `evaluate_one`

A feature flag `--isolation {off,pdf,on}` (default `pdf`):

- `off`: current in-process path (the only option before this deliverable; preserved for debugging & the determinism unit tests).
- `pdf`: PDF fixtures run via `run_isolated`; HTML stays in-process. **The default.**
- `on`: every fixture runs via `run_isolated`.

When isolated, `evaluate_one` receives a `WorkerOutcome` and converts it to the existing metrics shape. The metrics dict gains: `isolated: bool`, `duration_ms: int`, `peak_memory_bytes: int|None`, `worker_status: str`. A non-`success` worker status maps: `timeout`/`worker_crash`/`memory_limit` → `extraction_raises=1`, `passed=False`; `invalid_worker_output` → raises the harness-error path (exit 1).

The determinism check moves **inside** the worker (the child runs extraction twice and returns both fingerprints), so the parent does not spawn twice per fixture.

### Windows/POSIX asymmetry — documented honestly

The README and docstring state: on Windows (dev), wall-clock timeout works but memory/CPU limits do not (best-effort via exit-code inference). On Linux (CI), full RLIMIT_AS + RLIMIT_CPU + process-group kill. This is the pragmatic compromise the review endorsed.

## Deliverable 1c — Fixture criticality

### Schema (in `expected.json`)

```json
"expected": {
  "criticality": "critical",        // critical | standard | diagnostic (default standard)
  "required_gate": true,            // explicit; critical implies true
  "outcome": "no_content",          // existing, for graceful fixtures
  "max_duration_ms": 180000,        // optional, for the timeout tiers
  ...assertions...
}
```

Semantics: `critical` = admissions dates/eligibility/fees/merit lists/results/required docs; `standard` = ordinary informational; `diagnostic` = malformed/security/determinism/no-content fixtures.

### Scoring

The scorer's per-fixture metrics gain `criticality: str`. Aggregation gains a `by_criticality` roll-up alongside `per_family`:
```json
"by_criticality": {
  "critical":   {"fixtures": N, "pass_rate": ..., "block_recall": ..., ...},
  "standard":   {...},
  "diagnostic": {...}
}
```

### Gate enforcement

Critical fixtures enforce **separate, stricter** floors that cannot be compensated by standard/diagnostic improvements:
- Critical `pass_rate`: **100%** (hardcoded — not subject to `--min-pass-rate`).
- Critical `block_recall`: **100%**.
- Critical `extraction_raises`: **0**.
- Critical `determinism_rate`: **100%**.

A single failed critical fixture → exit 2 regardless of overall pass rate. `--wip` (Deliverable 1d) relaxes this only with the explicit override.

### Migrate the existing 29 fixtures

Author `criticality` per fixture based on family + content: admissions-php (fees, eligibility, deadlines, merit) → `critical`; pdf-download (prospectus, policies) → `critical` or `standard`; main-root → `standard`; fetch-failure + the 522/404 no-content → `diagnostic`. This is a small curated pass over the existing `_author_expectations` data, not new content.

## Deliverable 1d — Gate-weakening safeguards

### CLI changes

Replace the bare `--min-pass-rate` (which can be set to 0.0 accidentally) with:
- `--min-pass-rate FLOAT` (default `1.0`) — **valid only with `--wip`** if `< 1.0` or `< the critical floor`.
- `--wip` — explicit opt-in to relaxed thresholds. Prints a prominent stderr warning. Required to lower any gate floor.
- `--allow-malformed-fixtures` — also requires `--wip`.

### CI guard

```python
if os.getenv("CI") == "true" and args.wip:
    if os.getenv("ALLOW_WEAK_EXTRACTION_GATE") != "1":
        print("ERROR: --wip forbidden in CI without ALLOW_WEAK_EXTRACTION_GATE=1", file=sys.stderr)
        return 1
```

### Recorded gate config (in the report)

```json
"gate": {
  "mode": "strict",                 // "strict" | "wip"
  "min_pass_rate": 1.0,
  "critical_pass_rate": 1.0,        // always 1.0
  "require_determinism": true,
  "allow_malformed_fixtures": false,
  "isolation_scope": "pdf"          // off | pdf | on
}
```

The `--wip` warning is unmistakable: `⚠️  WIP MODE: quality gates are relaxed — do not merge on this run.`

## Tests (additive to the existing 49)

New `scripts/test_corpus_manifest.py`:
- Manifest hash is stable across two calls with unchanged fixtures.
- Removing/adding/relabelling a fixture changes the hash.
- Editing `expected.json` (incl. `criticality`) changes the hash.
- Editing `body.bin` changes `body_sha256` and the manifest hash.
- Malformed fixture dir → `null` hashes, no crash.

New `scripts/test_isolation.py`:
- A valid PDF fixture run via `run_isolated` returns `status="success"` and matches the in-process extraction's markdown (the two paths agree on a known fixture).
- A garbage-body PDF returns `status="success"` with `result.pdf_error.error_code="invalid_pdf"` (no parent crash).
- An invalid-worker-output scenario (simulate by pointing at a broken stub) → `status="invalid_worker_output"` → parent maps to exit 1.
- Timeout path: a request with `timeout_ms=1` against the prospectus → `status="timeout"` (the 4.6 MB PDF cannot convert in 1ms) → parent maps to `extraction_raises=1`, `passed=False`. (This is the slowest test; mark it `@unittest.skipIf(not PROSPECTUS_PRESENT)`.)

Extend `scripts/test_corpus_integrity.py`:
- Every fixture's `expected.criticality` (if present) is in `{critical, standard, diagnostic}`.
- `max_duration_ms` (if present) is a positive int.

Extend `scripts/test_extraction_eval.py`:
